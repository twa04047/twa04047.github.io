## StoryShaper — 아이가 이야기를 만드는 그림책

StoryShaper는 **부모의 목소리로 동화를 읽어주고, 아이의 답에 따라 다음 대사와 그림이 달라지는 대화형 그림책**입니다. 멀리 있는 부모도 자신의 목소리로 책을 읽어주고, 아이는 이야기를 듣다가 직접 선택하고 예상하며 사건의 이유를 말합니다. 팀원의 실제 육아 경험에서 출발한 프로젝트입니다.

데모의 동화는 「아기돼지 삼형제」입니다. 아이가 “얇은 종이!”라고 답하면 종이집으로 장면을 바꾸고, 집이 바람에 흩어지는 과정을 보여준 뒤 그 이유를 묻습니다. 기존 그림을 편집해 등장인물과 수채화풍 화풍을 이어갑니다. 부모가 녹음한 목소리로 다른 언어의 책을 읽는 기능도 팀의 제출 데모에 포함했습니다.

## 나의 역할 — 아이의 답을 다음 이야기로 연결하기

아이의 자유로운 답을 이해하면서도 동화의 인과관계와 안전한 결말을 지키는 에이전트를 설계·구현했습니다.

| 담당 영역 | 구현 내용 |
| --- | --- |
| 답 해석과 대사 생성 | Muse Spark로 아이의 의도와 재료를 해석하고, 현재 장면에 맞는 짧은 대사·다음 질문 생성 |
| 이야기 진행 설계 | 아기돼지 삼형제의 집 3채 각각에서 재료 고르기 → 결과 예상하기 → 이유 말하기를 구성해 총 9번 참여. 답을 확인한 뒤 다음 질문으로 연결 |
| 낯선 재료 처리 | 등록 목록에 없는 재료도 원문 이름·한영 명칭·물성을 검증하고, 이후 장면과 그림 요청까지 같은 재료 유지 |
| 안전 검증과 복구 | 서버 규칙 검사와 필요한 독립 모델 검토를 결합. 첫 미수용 답이나 음성 인식 실패 뒤에는 세 개의 터치 선택지로 전환 |
| 다른 기능과의 연결 | 아이의 선택과 검증한 이야기가 다음 그림과 낭독에 반영되도록 연결 |

## 자유로운 답과 고정된 사건 사이의 설계

이야기의 주요 사건과 결말은 사람이 정하고, 모델은 허용된 범위에서 아이의 선택을 해석하고 표현을 만듭니다. 서버는 모델이 제안한 재료·대사를 검사한 뒤 다음 상태를 확정합니다. 모델 응답 오류나 검토 실패가 생기면 진행 상태를 유지하고, 이를 아이의 실패로 세지 않습니다.

| 아이의 답과 상황 | 처리 원칙 |
| --- | --- |
| “종이로 지을래!” | 선택한 재료를 유지하고, 이후 바람에 흩어지는 사건과 이유 질문으로 연결 |
| “아이스크림 집!” | 말랑해짐 → 흘러내림 → 녹음의 관찰 과정을 설명. 늑대의 바람 때문에 녹았다고 표현하지 않도록 검증 |
| “더 커질 것 같아!”라는 예상 | 안전한 예상은 정답과 달라도 받아주고, 실제 변화 과정과 결과를 같은 응답 안에서 설명 |
| “늑대가 돼지를 먹어!” | 안전한 이야기 범위로 부드럽게 안내하고 세 개의 선택지로 참여를 이어가도록 복구 |

새 재료는 **가볍고 유연함·느슨한 조각·먹을 수 있음·녹음·단단함**의 다섯 물성으로 검증하고, 기존에 정의한 사건으로 연결했습니다. 예를 들어 종이컵을 종이로 단순 치환하지 않고, 아이가 말한 이름을 보존합니다. 해당 장면의 필수 사건과 맞지 않는 재료는 뜻을 인정한 뒤 다른 선택으로 안내합니다.

## 검증한 이야기만 그림과 음성으로 전달하기

팀의 전체 흐름은 **음성 전사 → 스토리 에이전트 → 장면 편집·검수 → 낭독과 화면 표시**입니다. Muse Voice Transcribe가 말을 듣고, Muse Spark가 답을 해석하고 대사를 작성하며, Muse Image가 현재 그림을 편집합니다. 생성된 그림도 Muse Spark로 별도 검수합니다. 제출 데모에서는 SAM 3.1로 분리한 그림 요소를 애니메이션에 활용했습니다.

## 가드레일·프롬프트 엔지니어링·응답 속도 개선

**에이전트 가드레일 적용.** 동화의 주요 사건과 안전한 결말을 규칙으로 정하고, 생성한 재료·대사·질문을 검증한 뒤 이야기를 진행하도록 설계했습니다. 낯선 재료나 복잡한 답은 별도로 다시 검토하고, 부적절하거나 이해하기 어려운 답에는 부드러운 설명과 세 가지 선택지를 제공하도록 했습니다.

**프롬프트 엔지니어링.** 현재 질문의 목적, 아이가 고른 재료와 그 특성, 쉬운 표현 기준을 프롬프트에 담았습니다. 아이의 예상이 실제 결과와 달라도 생각을 먼저 받아주고, 눈으로 관찰할 수 있는 변화 → 결과 → 쉬운 질문으로 이어지도록 대사 생성 지시를 다듬었습니다. 아이가 말한 재료 이름을 다른 재료로 바꾸거나 사건의 원인을 잘못 설명하는 문제도 개선했습니다.

**응답 속도 최적화.** 현재 장면에 필요한 정보만 전달하도록 중복 문맥을 줄였습니다. 단순한 답은 규칙 검사 후 바로 진행하고, 새 재료나 복잡한 답에는 추가 검토를 유지하도록 호출 흐름을 개선했습니다. 준비된 선택지에는 미리 작성한 대사를 재사용해 모델 호출을 줄였고, 모형 테스트로 요청 수와 입력량의 감소를 확인했습니다.
