## 내가 맡은 문제와 해결

보험사 제안을 위한 UBI(Usage-Based Insurance) 분석에서, 트럭 등 대형차의 운행 기록과 보험 사고 이력을 연결해 **사고 차량과 무사고 차량의 운전습관 차이**를 분석했습니다. 초 단위로 쌓이는 기록을 차량별 비교 지표로 바꾸는 전처리·집계·분석 코드를 개발했습니다.

핵심 과제는 반복 작업과 처리시간이었습니다. **Excel 중심 업무를 Python으로 자동화**하고, **일반 for문으로 행을 순회하던 핵심 계산을 pandas 컬럼 연산으로 바꾸어 처리속도를 11배 개선**했습니다. 분석·판정 기준은 주어진 기준을 구현했으며, 데이터 처리와 결과 생성 코드를 담당했습니다.

## 전체 데이터 처리 프로세스

```ubi-process
```

운행 기록에서 속도 변화, 방향각, RPM, 브레이크 신호를 계산하고, 트립별 결과를 차량 단위로 집계했습니다. 운행거리·시간으로 비율을 만들어 차량마다 다른 운행량을 보정한 뒤, 보험 사고 이력을 익명 차량 ID로 연결했습니다.

| 분석 관점 | 대표 피처 | 사용하는 기록 |
| --- | --- | --- |
| 속도 변화 | 급가속·급감속·급정지 | 속도 차분, 브레이크 신호 |
| 방향 변화 | 급진로변경·급회전 | 방향각 차분, 이동 구간 누적값 |
| 운행 상태 | 과속·정속·고RPM·야간운전 | 속도, RPM, 수집 시각 |
| 차량 간 비교 | 거리·시간 대비 발생 비율 | 트립 운행거리, 주행시간 |

**사고회수 0은 무사고군, 1 이상은 사고군**으로 구분했습니다. 사고정보가 연결된 차량을 대상으로 F검정과 독립표본 T-Test를 수행해 두 집단의 지표 차이를 비교했습니다. 이 집단 구분은 관측된 사고 이력에 따른 것이며, T-Test는 집단 간 평균 차이를 검정하는 단계입니다.

## for문에서 pandas로, 11배 빠르게

```ubi-performance
```

기존에는 레코드를 하나씩 순회하며 이전 값과 비교하고 조건에 맞는 횟수를 누적했습니다. 이를 **컬럼 전체의 차분·조건식·구간 연산·집계**로 옮겨 반복문의 부담을 줄였습니다.

| 계산 작업 | 변경한 처리 방식 |
| --- | --- |
| 이전 시점과 속도·방향각 비교 | `diff()`로 컬럼 차분 계산 |
| 일정 구간의 변화량 계산 | `rolling()`·`shift()`로 구간 연산 |
| 조건에 맞는 운행 기록 집계 | 불리언 마스크와 `sum()`, NumPy 조건 연산 |
| 여러 트립의 차량별 결과 통합 | `groupby()` 기반 합산 |

최적화의 핵심은 **각 레코드에 수행하는 반복 계산의 벡터화**입니다. 파일과 트립을 순회하는 바깥 반복문은 유지하면서, 많은 행에 반복 적용되는 계산을 pandas로 처리했습니다.

```python
# 처리 방식 설명을 위한 축약 예시: 동일 차량·동일 트립, 시간순 정렬 전제
speed_change = trip["SPEED"].diff()
high_rpm_time = (trip["RPM"] > rpm_threshold).sum()
direction_window = trip["DIRECTION"].diff().rolling(5).sum()
```

실제 방향각 계산에는 0°/359° 경계 보정과 조건별 필터가 추가됩니다. 초 단위 횟수를 시간으로 해석할 때에는 기록 간격과 누락·중복 여부도 고려해야 합니다.

## Excel 반복 업무를 Python으로 자동화

보험 Excel을 읽는 단계부터 결과 Excel을 만드는 단계까지 연결했습니다. 데이터가 바뀔 때마다 시트와 수식을 수작업으로 다루던 업무를, 코드에 정의한 정제·집계·분석 절차로 수행하도록 바꿨습니다.

| 업무 | Python으로 구현한 처리 |
| --- | --- |
| 보험 자료 취합 | 여러 Excel 시트 읽기, 설명 행 제거, 데이터 통합 |
| 분석 대상 정리 | 소유 기준일·사고일자 필터, 결측·미확정 보험금 처리 |
| 차량별 사고정보 정리 | 사고회수·보험금 집계, 익명 시리얼 번호 매핑 |
| 운행 지표와 결합 | 차량별 운전습관 피처에 보험 사고 이력 연결 |
| 비교 결과 작성 | 통계 검정, 결과표와 분포 그래프, Excel·CSV 출력 |

수작업의 각 단계를 실행 가능한 코드로 남겨, 같은 처리 규칙을 반복 적용하고 변경된 기준에 맞춰 결과를 다시 생성할 수 있게 했습니다.

## 데이터 형태: 컬럼과 가상 예시

**아래 값은 형태를 설명하기 위해 새로 만든 가상 데이터입니다.** 실제 차량 식별자, 운행 시각, 주행 기록, 보험 이력은 공개하지 않습니다. `VIN`은 분석 파일에서 익명 시리얼 번호를 담는 컬럼입니다.

| 컬럼 | 의미 | 가상 예시 |
| --- | --- | --- |
| `VIN` | 익명 차량 식별자 | `DEMO-001` |
| `TRIP_DATE` | 운행 일자 | `2030-01-01` |
| `TRIP_COUNT` | 일자 내 운행 차수 | `1` |
| `TRIP_TIME` | 레코드 수집 시각 | `2030-01-01 09:00:00` |
| `RPM` | 엔진 회전수 | `1,200` |
| `SPEED` | 차량 속도 · km/h | `40` |
| `DIRECTION` | 방향각 · 0~359° | `90` |
| `ACCEL_X` | X축 가속도 원문값 | `1.0` |
| `ACCEL_Y` | Y축 가속도 원문값 | `0.0` |
| `BRAKE_YN` | 브레이크 신호 코드 | `48` |
| `DAY_DISTANCE` | 일 운행거리 누계 | `12` |
| `TOTAL_DISTANCE` | 총 누적운행거리 | `10,012` |
| `STATUS` | DTG 장치 상태 코드 | `0` |

다음은 주요 컬럼만 펼친 3초 분량의 가상 시계열입니다. 같은 차량의 같은 트립 안에서 값이 시간순으로 쌓이는 구조를 보여줍니다.

| VIN | TRIP_TIME | SPEED | RPM | DIRECTION | BRAKE_YN |
| --- | --- | ---: | ---: | ---: | ---: |
| DEMO-001 | 2030-01-01 09:00:00 | 40 | 1,200 | 90 | 48 |
| DEMO-001 | 2030-01-01 09:00:01 | 42 | 1,250 | 91 | 48 |
| DEMO-001 | 2030-01-01 09:00:02 | 39 | 1,180 | 91 | 49 |

`BRAKE_YN`은 파서에서 문자 `0/1`을 ASCII 코드 `48/49`로 저장한 형식입니다. 가속도·거리·장치 상태 값의 해석은 원천 포맷과 처리 코드에 따릅니다.
