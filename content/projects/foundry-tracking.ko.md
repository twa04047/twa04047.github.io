## 프로젝트 개요

이동형 불법셀의 의심 징후와 이동 이력을 함께 살펴볼 수 있도록 **Palantir Foundry 기반 모니터링 PoC**를 개발했습니다. 통신 로그를 가공해 이상 후보를 좁히고, 지도에서 시간에 따른 이동을 확인하는 업무 흐름을 구성했습니다.

원시 로그만으로는 어떤 셀을 먼저 확인해야 하는지, 어떤 지표가 이상 판단의 근거인지, 여러 시점의 위치가 어떻게 이어지는지 파악하기 어렵습니다. 이를 **이상 플래그 모니터링**과 **이동 경로 탐색** 화면으로 나눠 표현했습니다.

공개 범위는 더미데이터로 구현한 PoC입니다. 화면에 등장하는 셀·대상 식별자, 좌표, 기간과 수치는 기능을 설명하기 위한 예시이며 실제 불법셀 적발 결과를 의미하지 않습니다.

## 나의 역할과 구현 범위

위치 추적 로직과 전처리를 개발하고, 결과를 사용자가 탐색할 수 있도록 Workshop UI/UX를 구성했습니다. 데이터 변환 결과를 지도에 표시하는 데 필요한 좌표·경로 구조와 화면의 선택·필터 흐름을 함께 다뤘습니다.

| 영역 | 구현 내용 | 화면에서의 쓰임 |
| --- | --- | --- |
| 데이터 가공 | 통신 이벤트의 시간·셀 정보를 정리하고 일별 지표와 플래그로 집계 | 이상 후보와 판단 근거 확인 |
| 위치 추적 | 접속 전후 이력과 위치 메타데이터를 결합하고 방문 구간을 생성 | 방문 지역과 이동 순서 탐색 |
| Ontology 연결 | 가공 데이터를 객체와 관계로 연결 | 선택한 셀의 요약·상세 정보 조회 |
| Workshop UI/UX | 대상 목록, 지표 상세, 지도·타임라인·차트 구성 | 후보 검토와 경로 확인 |

## 데이터가 화면에 도달하는 구조

모니터링 파이프라인은 더미 통신 로그를 일별 마트로 가공한 뒤, **최종 플래그용 데이터와 상세 지표용 데이터를 분리**합니다. 두 결과를 Ontology 객체로 연결하고 Workshop에서 함께 조회하도록 구성했습니다.

![더미데이터 기반 Data Lineage. 일별 마트가 플래그·상세 데이터셋으로 분기하고, 서로 연결된 두 객체를 통해 Workshop 모니터링 화면에 도달합니다.](../../../media/foundry/data-lineage.png)

| 단계 | 처리 내용 |
| --- | --- |
| 입력 | 셀 식별자, 접속 시작·종료 시각, 가입자 구분값과 메시지 유형을 가진 더미 이벤트 |
| Pipeline Builder | 이벤트 정리, 시간·대상별 집계, 세부 지표 및 최종 플래그 생성 |
| Ontology | 이상 탐지 요약 객체와 일별 상세 객체 연결 |
| Workshop | 대상 선택에 맞춰 플래그, 상세 지표와 설정값을 표시 |

![더미데이터 기반 Pipeline Builder 전처리 구성. 여러 지표 계산을 분기한 뒤 모니터링용 출력으로 연결했습니다.](../../../media/foundry/pipeline-builder.png)

전처리를 단계별로 구성해 화면의 최종 결과가 어느 데이터와 계산에서 나왔는지 거슬러 확인할 수 있도록 했습니다. [전처리 원본 화면 크게 보기](../../../media/foundry/pipeline-builder.png)

## 이상 플래그와 판단 근거 확인

모니터링 화면은 왼쪽에 전체 셀과 비정상 후보 목록을, 중앙에 선택한 셀의 최종·세부 플래그를 배치했습니다. 운영자가 후보를 선택한 뒤 관련 지표를 연속해서 읽을 수 있는 구조입니다.

![더미데이터 기반 이상 플래그 모니터링 화면. 왼쪽은 셀 목록, 중앙은 최종·세부 플래그와 지표, 오른쪽은 설정값 패널입니다.](../../../media/foundry/flag-monitoring.png)

접속 시간, 가입자 수, 메시지 관련 지표를 함께 보여주어 단일 이상 여부 표시에서 세부 근거로 이어지도록 했습니다. 화면에는 설정값 패널과 설정 변경 진입 버튼도 배치했습니다. 캡처에 보이는 값은 PoC 설정 예시입니다.

플래그는 **추가 검토할 후보를 찾기 위한 신호**이며, 세부 지표와 이동 이력을 함께 검토하도록 구성했습니다.

## 시간에 따라 이어지는 이동 경로

위치 추적 처리에서는 대상 셀의 접속 전후 이력에 위치 메타데이터를 결합합니다. 보관 PySpark 코드에는 좌표 형식 변환, 시간순 정렬, 방문 지역이 바뀌는 지점의 구간화, 구간별 대표 좌표 집계와 경로 선분 생성이 구현되어 있습니다.

1. **이력 연결:** 대상 접속 전후의 관련 이벤트를 연결해 위치를 추정할 자료를 구성합니다.
2. **방문 구간 생성:** 같은 지역의 연속 방문을 묶고 시작·종료 시각과 대표 좌표를 계산합니다.
3. **공간 데이터 변환:** 좌표를 정규화하고 GeoPoint, 이동 방향과 GeoJSON 경로 선분을 만듭니다.
4. **화면 탐색:** 대상을 선택하고 방문 지역·체류시간을 확인하며 지도 타임라인으로 이동 흐름을 살펴봅니다.

경로 탐색 화면에는 대상 선택기, 방문 주소 개수, 지역별 방문 분포, 체류시간 차트와 지도 타임라인을 함께 배치했습니다. 위의 원본 영상에서는 대상 변경과 타임라인 조작에 따른 경로 표시를 확인할 수 있습니다.

지도 선은 관측·집계된 위치를 시간순으로 연결한 표현입니다. 실제 도로 주행 경로나 GPS 수준의 위치 정확도를 의미하지 않습니다.

## 구현 과정에서 다룬 설계 문제

**요약과 상세의 연결.** 이상 여부를 빠르게 훑는 화면과 판단 근거를 읽는 화면에 필요한 데이터 수준이 다릅니다. 플래그와 상세 지표를 분리하고 객체 관계로 연결해, 같은 셀을 기준으로 두 수준의 정보를 확인하도록 구성했습니다.

**로그를 지도 객체로 변환.** 좌표가 있어도 화면에 바로 이동 경로가 생기는 것은 아닙니다. 시간순 방문 구간, 대표 위치와 다음 지점의 관계를 계산하고 지도에서 사용할 공간 속성으로 변환했습니다.

**데이터 의존성과 화면 변수.** 구현과 함께 입력·출력 데이터셋의 순환 의존성 문제를 문서화했습니다. TypeScript Function·Ontology·Workshop 선택 변수의 연결 방법은 별도 예제를 활용한 기술 자료로 정리했습니다.
